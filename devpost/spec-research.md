## Convex Auth and Email

[Convex Auth](https://labs.convex.dev/auth) supports React Native and password authentication, including reset and optional verification. It remains labelled beta. The learner has already chosen it; this investigation does not reopen Clerk versus Convex Auth.

The documented [Password provider](https://labs.convex.dev/auth/config/passwords) uses `signUp`, `signIn`, `reset`, `reset-verification`, and `email-verification` flows. `reset` and `verify` accept email-provider configurations. Reset links require routing to the new-password step; the documentation also shows OTP examples. Implement the PRD's secure reset link rather than silently replacing it with a code-only flow. Password confirmation belongs in the form, with password validation also enforced by the backend. Failed delivery and expired verification must expose retry. The docs are evidence of library support; Android email-link behavior remains an early real-device test.

The [React API](https://labs.convex.dev/auth/api_reference/react) requires a `storage` adapter in React Native and recommends wrapping `expo-secure-store`. It provides `getItem`, `setItem`, and `removeItem`, including asynchronous implementations. Use protected persistent token storage, separate from downloaded learning data. Its `useAuthToken` is for Convex HTTP actions; do not forward that token to model providers. Native code-handling must be deliberate so a reset link is handled by the password-reset screen rather than consumed as a generic sign-in code.

The [server API](https://labs.convex.dev/auth/api_reference/server) exposes credential helpers, but separate current-password verification and credential modification do not make an atomic change. Following the learner's concurrency review, Settings will use the same verified email reset as recovery, with an authenticated lookup of that account's email and no application credential-update action. The reset returns its own session; do not promise to retain the previous Settings session. Locked-version token/session behavior and concurrent completions remain acceptance tests. See `service-contract-research.md > Settings Password Change`.

**Learner-selected email service:** Resend, confirmed with "yes use resend." Plan for its free tier. Its [testing-domain restriction](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain) permits testing mail only to the Resend account's own address. Other learners require a verified sending domain and a sender on that domain. Its [pricing page](https://resend.com/pricing) currently lists a free-plan daily limit of 100; confirm account-specific monthly/API limits before finalizing the service budget. Public signup success cannot be proved with owner-only test mail. Configure and verify the actual sender/domain during setup; no domain value or completed DNS verification has been recorded.

[Android App Links](https://docs.expo.dev/linking/android-app-links/) require domain association and app configuration. A landing domain could host the association file and an app-opening/install handoff without adding a web learning or account interface. Domain ownership, installation method, token routing, link expiry, and fresh-install/cold-start behavior need to be settled and tested. Custom-scheme links are another implementation option; their email-client behavior must be tested rather than assumed.

## Offline Storage and Synchronization

Convex's [sync overview](https://www.convex.dev/sync) explicitly says it handles intermittent network issues but does not provide a full offline synchronization mechanism. Therefore the PRD's restart-safe offline work cannot rely solely on the Convex React client's pending writes.

[Expo SQLite for SDK 55](https://docs.expo.dev/versions/v55.0.0/sdk/sqlite/) is the agreed persistent phone store. **Learner accepted this architecture with "yes":** SQLite holds versioned lesson packages, approved answers, resumable position, queued study events, and cached progress; persistent files hold downloaded audio and recording attempts. Convex remains the shared account history. Each attempt has a stable unique ID so retrying synchronization counts it once and retains its original study date. The same TypeScript review rules run locally and on the backend. The app acknowledges local work only after its local transaction commits, then synchronizes an outbox when connectivity and authentication permit.

Each queued attempt should have a stable unique event ID, account/device association, content/algorithm version, original occurrence timestamp, original local calendar date/timezone, input/support method, and assessment state. A [Convex mutation](https://docs.convex.dev/functions/mutation-functions) can atomically deduplicate a batch and update derived progress. This is a proposed contract, not a claim that an offline sync library already does it.

The revised spec defines atomic first-server-commit closure of each due review opportunity. Its accepted result and successors are permanent; later stale successes/failures remain original-day study and skill evidence without rewriting acknowledged schedule/mastery. Matching offline chains can be accepted through their stable parent resolutions; conflicting unacknowledged branches remain extra practice, with explicit provisional UI. This is a proposed application rule, not Convex's built-in offline behavior. Test closure immutability, both conflicting arrival orders with their respective winners, long-delayed failures, offline ancestry, and lost acknowledgements. Do not claim conflicting arrival orders choose an identical winner.

## AI Routing and Agent Workflow

Cloudflare [AI Gateway provider support](https://developers.cloudflare.com/ai-gateway/usage/providers/) includes Google AI Studio, OpenRouter, Groq, and Workers AI. The learner requires all model connections through this gateway and two real configured conversation providers behind an adapter. They accepted Gemini 3.8 Flash as primary and OpenRouter's free Nemotron 3 Super as the initial alternative, subject to Japanese-quality and tool-calling acceptance checks. No authenticated provider switching has been demonstrated yet.

The [Google AI Studio gateway](https://developers.cloudflare.com/ai-gateway/usage/providers/google-ai-studio/) exposes `https://gateway.ai.cloudflare.com/v1/{account}/{gateway}/google-ai-studio` with the provider endpoint appended. Requests can include `x-goog-api-key` and `cf-aig-authorization`. Its examples include native `generateContent`; newer speech model paths and payloads need separate verification. [Groq's gateway](https://developers.cloudflare.com/ai-gateway/usage/providers/groq/) is another provider candidate. [Workers AI gateway routing](https://developers.cloudflare.com/ai-gateway/usage/providers/workersai/) is also documented. Use explicit provider configuration; do not confuse Cloudflare AI Gateway with Vercel AI Gateway.

[Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/) currently includes 10,000 neurons per day shared across models, resetting at 00:00 UTC. Beyond that requires a paid plan; some listed models require paid billing even before that. Free capacity is not an unlimited-demo promise. Keep app-level request limits, finite retries, timeouts, and service-failure fallbacks in the spec. Any paid fallback requires the learner's budget decision.

**Learner-agreed architecture:** authenticated [Convex actions](https://docs.convex.dev/functions/actions) load the learner and session context, call a server-only provider adapter, and commit normalized results through mutations. Keep API secrets off Android and off the public landing site. External failures retain pending messages instead of inventing replies or modifying mastery.

[AI SDK's ToolLoopAgent](https://ai-sdk.dev/docs/agents/building-agents) offers reusable model/tool configuration and a bounded tool-calling loop. The learner agreed to use this small agent to look up relevant Qloo contexts and approved lesson/grammar records before producing level-appropriate conversation and corrections. This is a selected implementation direction, not an assertion of event eligibility. An adapter and a strict result schema should isolate provider-specific behavior. Review scheduling, active-time accounting, ownership, and acceptance of approved fixed answers should remain deterministic application logic.
